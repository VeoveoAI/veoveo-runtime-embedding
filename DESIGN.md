# Private embedding runtime

This component is a thin upstream Sentence Transformers/PyTorch process. Hub identity, MCP permissions, registration and nonmonetary token usage belong to the Rust MCP service. Runtime auth is one fixed operator bearer held by native provider custody. It has no user identity database, content storage or vector search.

The first semantic space fixes EmbeddingGemma 2 revision `914f7f89142e33e77833254d9c9b90c3cef7303b`, 768 dimensions, upstream mean pooling/projection/normalization and text-only input. `contract.PROCESSING` hashes a sorted compact semantic descriptor into `PROCESSING_ID`; GPU device, FP32 dtype and source/package versions are separate execution provenance. Search query prompt is `task: search result | query: `; code query prompt is `task: code retrieval | query: `; document prompt is `title: {title_or_none} | text: {content}`. Absent title uses literal `none`. Render once and pass prompt="" to upstream encode to avoid double prompting.

Startup requires the canonical pinned HF cache offline, exact reviewed dependency versions, explicit MPS/CUDA availability, FP32 GPU parameters, fixed prompts/pooling/dimensions. Native lower-transformer input hooks observe actual GPU forward placement. Upstream may return final CPU tensors for serialization; this is not CPU inference. No fallback or per-request download/path selection exists. Source/image commit and cache snapshot/file hashes belong to qualification evidence, not a second cache format.

Native Sentence Transformers/tokenizer max-length metadata may be an unspecified-length sentinel; it is not the API token limit and need not equal 8192. The pinned checkpoint's actual context is qualified separately. We do not overwrite upstream model/tokenizer lengths. Input and JSON validation have byte/item bounds before inference. The same native processor as encode counts every fully rendered item with truncation disabled and includes special tokens. Reject any item >8192 tokens or sum >16384, before any model call. Use native encode batch_size=2 under one GPU admission slot; each padded microbatch is at most 2x8192 tokens, and upstream restores order. Preflight and full-result validation prevent partial output. Every vector must be finite, normalized and 768-dimensional.

The one-slot admission guard is held by the actual worker thread. HTTP timeout/cancellation shields the worker, retains its reference and keeps the slot occupied until completion; a new caller gets busy. No queue, retries, cancellation promise for GPU kernels, custom scheduler or durable Tasks are introduced. A caller retry computes again. Native OS/container shutdown owns final process termination.

Errors use a closed vocabulary without input, tensors, credentials or upstream error bodies. The runtime returns explicit execution classification. Definitive validation/auth/busy/not-ready failures are not_started; timeouts or failures once work may have begun are unknown. The MCP preserves conservative usage estimates for ambiguous outcomes, writes zero actual only for explicit pre-execution rejection, and records actual tokenizer counts on validated success. Runtime stores no usage or content itself. Access logging is disabled; upstream inference exceptions are replaced without chaining their text.

Pinned Python/uv and platform-marked model wheels are in pyproject/uv.lock. Native Mac MPS and Linux/amd64 cu130 are inference targets. Linux/arm64 is intentionally valid for the deterministic base check without model dependencies; unsupported inference platforms fail startup. Tests use synthetic count/model seams and vectors to exercise bounds, native batch-size selection, order, failure classification and live-worker admission; they cannot prove tokenizer semantics or model quality. Real runtime MPS and later CUDA acceptance remain separate from prerequisite probes and deterministic checks.
